# حزمة مهارات تحسين جودة الفحص

الحزمة `reconhawk-quality-pack.json` تتضمن ثمانية playbooks مخصصة ذات أسماء تبدأ بـ `RHQ v1`.
هي تعليمات عمل ومراجعة للأدلة، وليست أدوات تنفيذ جديدة أو ضماناً لاكتشاف الثغرات.
بعض موضوعاتها تتقاطع مع المهارات الافتراضية؛ قيمتها في الضوابط والأدلة وحدود التوقف، وليس
في زيادة الرقم المعروض للمهارات.

## ما الذي تضيفه؟

1. تكوين طلب API صحيح من العقد أو المصدر قبل تفسير نتائج الاختبار.
2. مصفوفة صلاحيات لهويتين وموارد يملكها المشغّل، مع طلبات تحكم واضحة.
3. فحص ضمانات إبطال الجلسات وتغيير الأدوار قبل/بعد الحدث المصرّح.
4. استعلام GraphQL صغير واختبار صلاحيات الكائن/الحقل دون batching أو تحميل زائد.
5. ثوابت OAuth/OIDC باستخدام حسابات وعمليات رجوع يسيطر عليها المشغّل.
6. عزل المحتوى الخاص في الكاش وحدود CORS مع إثبات تأثير فعلي، لا ترويسات وحدها.
7. اختبار قاعدة عمل واحدة بموارد قابلة للعكس وموافقة محددة على تغيير الحالة.
8. مراجعة الأدلة وإغلاق الأفكار والـLeads وتسجيل ما بقي غير مختبر بصراحة.

كل playbook يحدد المتطلبات، وحداً صغيراً لعدد الطلبات، وضوابط إيجابية وسلبية، وأرقام طلبات
الإثبات المطلوبة، وأسباب النتائج الكاذبة، وحالات التوقف أو عدم كفاية الدليل. لا تمنح أي مهارة
إذن فحص هدف جديد أو تجاوز سياسة البرنامج. إذا غابت هوية/عينة/أداة لازمة، النتيجة غير محسومة.

## الاستيراد الاختياري

الحزمة لا تُضاف إلى قاعدة البيانات ولا تُفعّل تلقائياً عند تشغيل المشروع. ملف الحزمة هو جسم
طلب API مطابق للمستورد الحالي: كائن `files` يحتوي ثمانية ملفات Markdown مستقلة. واجهة الرفع
العادية تقرأ ملفاً واحداً كمهارة واحدة، لذلك **لا ترفع ملف الحزمة كاملاً بزر Upload**.

من جذر المشروع وعلى نفس جهاز الخلفية، بعد مراجعة الحزمة، يمكن استيرادها صراحةً:

```bash
curl --fail-with-body \
  -H 'Content-Type: application/json' \
  --data-binary @skills/reconhawk-quality-pack.json \
  http://localhost:8000/api/skills/upload
```

غيّر المنفذ إلى منفذ الخلفية الفعلي، مثل `9000`. إذا ضبطت رمز وصول للـAPI، أضف ترويسة
`Authorization: Bearer ...` بطريقتك المعتادة الآمنة. لا تضع رمزك داخل ملف الحزمة أو المستودع.

الاستيراد الحالي **يفعّل المهارات المخصصة المرفوعة**. بعده افتح Knowledge → Skills، وراجع
الأسماء الثمانية وحالة التفعيل. عطّل المهارات المتداخلة التي لا تحتاجها حتى لا يتضخم سياق الوكيل.
إعادة استيراد الحزمة تحدّث مهارات RHQ v1 نفسها وتعيد تفعيلها، ولا تضيف ثماني نسخ جديدة.

إذا تفضّل الرفع بالواجهة، يمكن استخراج عناصر `files` إلى مجلد تختاره بواسطة `jq` من جذر المشروع:

```bash
mkdir -p work/quality-playbooks
jq -r '.files[] | @base64' skills/reconhawk-quality-pack.json |
while IFS= read -r item; do
  name=$(printf '%s' "$item" | base64 -d | jq -r '.filename')
  printf '%s' "$item" | base64 -d | jq -r '.content' > "work/quality-playbooks/$name"
done
```

بعدها ارفع ملفات Markdown الثمانية من `work/quality-playbooks` في Knowledge → Skills.
هذا المثال مخصص للحزمة المراجعة المرفقة ذات أسماء ملفات ثابتة، وليس مستخرجاً آمناً لملفات JSON
غير موثوقة. تحتاج أداة `jq` لهذا الخيار فقط.

## التحقق والحدود

الاختبارات المحلية تتحقق من توافق كل عنصر مع `_parse_skill_file`، وأسماء المهارات، وعناصر
الدليل والضوابط والتوقف. لا تستخدم الاختبارات أهدافاً حقيقية، ولا تثبت أن الوكيل ينفّذ كل خطوة
بنجاح مع كل موديل. معلومات الحسابات والملكية والواجهات الموثقة يزوّدها المشغّل. قد تحتاج بعض
تدفقات OAuth أو إثبات CORS إلى خطوات بشرية بسبب أدوات المتصفح المتاحة.

سجل التغطية الذي تطلبه المهارة الأخيرة هو ملخص يراجعه المشغّل، وليس محرك تغطية حتمياً مطبقاً
في هذا الإصدار. كذلك لا تعالج هذه المهارات عيوب العزل أو النطاق أو سباقات التحقق بحد ذاتها؛
تلك تحتاج قيوداً واختبارات في الكود.
